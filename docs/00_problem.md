# 00. 문제 정의

## 리서치 병목
일반 LLM 리서치 도구는 사용자의 질문을 그대로 검색어로 바꿔 **자연스러운 요약문**을 만든다.
그러나 컨설팅 실무에서 시니어가 원하는 것은 "그럴듯한 글"이 아니라
**어떤 판단을 할 수 있고, 무엇이 아직 비어 있는지**다.

현재 방식의 문제:
- 사용자 질문이 그대로 결론이 되어 뉴스 요약에 머문다.
- 사실/전망/추론/홍보가 섞인다.
- 근거 위치가 없어 숫자를 다시 검증해야 한다.
- 중요한 이슈 누락 여부를 알기 어렵다.
- 경쟁사 비교·리스크가 일관된 축으로 정리되지 않는다.

## 목표
- 사용자 질문 → **이슈트리 + 가설**로 분해
- 이슈별 **근거 claim** 수집(출처·문단·날짜·범위 보존)
- 소스 간 일치/충돌/범위 차이/**근거 공백** 표면화
- 시니어가 바로 리뷰하는 **fact pack** 산출

## 중요한 구분
사용자 입력("한화오션 수주잔고 및 전망")은 **리서치 요청**이지 claim이 아니다.
Claim은 자료에서 추출된 **검증 가능한 최소 주장 단위**여야 한다.
